# ppt/

PowerPoint 실습용 폴더. **"기존 덱을 Claude에게 주고 같은 디자인으로 새 덱을 만들게 한다"** 는 실습에 쓴다.

수강생이 실제로 원하는 건 요약이 아니라 재현이다. 회사에 이미 쓰던 덱이 있고, 그 디자인 그대로 내용만 바꾼 새 장표를 뽑고 싶어한다. 이 폴더의 파일은 그 흐름을 연습하기 위한 입력이다.

## 파일 목록

| 파일 | 내용 | 용량 |
|---|---|---|
| `ictk_deck_template.pptx` | 사내 발표 템플릿. 15슬라이드, **본문 레이아웃 10종(A~J)**, 발표자 노트 15개, 텍스트는 전부 플레이스홀더. 슬라이드 1에 Style Guide 내장 | 4.8MB |
| `creative_brief_deck.pptx` | 크리에이티브 브리프 템플릿. 10슬라이드, 사진 16장, 텍스트는 전부 Lorem ipsum | 5.3MB |
| [`ictk_deck_template.DESIGN.md`](ictk_deck_template.DESIGN.md) | 위 템플릿의 디자인 시스템 | 문서 |
| [`creative_brief_deck.DESIGN.md`](creative_brief_deck.DESIGN.md) | 브리프 덱의 디자인 시스템 | 문서 |
| [`DESIGN-METHOD.md`](DESIGN-METHOD.md) | **아무 pptx에서나 위 문서를 뽑아내는 방법** — 절차 10단계, 추출 스크립트, 프롬프트, 검증법 | 문서 |

두 덱은 성격이 정반대라 짝으로 쓴다.

| | `ictk_deck_template` | `creative_brief_deck` |
|---|---|---|
| 출처 | **코드 생성**(PptxGenJS) | 다운로드(Canva 무료 템플릿) |
| 성격 | 정보 밀도 높은 사내 발표용 | 이미지 중심 디자인 덱 |
| 위계 만드는 법 | **위치와 색** (좌 근거 / 우 네이비 패널에 결론) | **크기 대비** (본문 16pt ↔ 제목 195pt) |
| 색 | 12색, 역할별로 갈림 | 3색 |
| 폰트 | Noto Sans KR (무료) | 상용 폰트 4종, 파일에 임베드 |
| 좌표 | 0.75 배수로 정확히 떨어짐 | 자동 맞춤이 곱해져 어중간 |
| 난이도 | **먼저** — 규칙이 그대로 남아 있어 역산이 쉽다 | 나중 — 손으로 만든 덱 다루기 |

## 실습 흐름

1. **분해** — 덱에서 디자인 스펙을 뽑아 `*.DESIGN.md`로 적는다. 캔버스, 색, 폰트·자간, 여백, 레이아웃 패턴.
2. **재작성** — 그 문서만 보고 내용을 우리 것으로 바꾼 새 pptx를 만든다. python-pptx 또는 PptxGenJS.
3. **대조** — 원본과 나란히 열어 어긋난 지점을 찾는다. 대개 자간·캔버스 크기·여백에서 틀어진다.

1단계 정답과 추출 방법은 `*.DESIGN.md`와 [`DESIGN-METHOD.md`](DESIGN-METHOD.md)에 있다. 먼저 직접 뽑아본 뒤 대조하는 용도이니, 실습 전에 열어 보여주지 말 것.

## 대표 실습 — 제안서(md)를 발표 덱으로

가장 현실에 가까운 과제다. 이미 쓴 문서가 있고, 그걸 회사 템플릿에 맞춰 발표 자료로 바꿔야 하는 상황.

**입력 두 개:**

- 내용 → [`business-docs/references/지난제안서.md`](../business-docs/references/지난제안서.md) (스마트미터 보안칩 적용 제안서, 9개 절)
- 디자인 → `ictk_deck_template.pptx` + [`ictk_deck_template.DESIGN.md`](ictk_deck_template.DESIGN.md)

**절 ↔ 레이아웃 매핑.** 제안서 9개 절이 템플릿 레이아웃에 거의 그대로 대응한다. 이 표를 정답으로 주지 말고, 수강생이 먼저 짜 보게 한 뒤 비교한다.

| 제안서 절 | 내용 성격 | 맞는 레이아웃 |
|---|---|---|
| 1. 제안 배경 | 문제 두 가지 | **A** 근거·결론 분할 — 좌측 카드에 문제, 우측 패널에 "그래서 필요한 것" |
| 2. 현황 분석 | 현재 ↔ 요구 수준 표 | **D** 대비 또는 **E** 비교표 |
| 3. 제안 내용 | 3-1·3-2·3-3 세 갈래 | **B** 병렬 항목 |
| 4. 도입 절차 | 단계 진행 | **H** 2단 연혁 |
| 5. 일정 | 기간별 진행 | **C** 타임라인 — 우측 패널에 총 소요 기간 |
| 6. 투자 비용 | 금액 항목 | **E** 비교표 + **C**의 수치 패널(48pt) |
| 7. 기대 효과 | 정량·정성 효과 | **F** 기능 나열, 첫 칸에 대표 효과 |
| 8. 회사 소개 | 기본 정보 | **I** 회사 개요 |
| 9. 문의처 | 담당자 연락처 | 클로징(15) |

**프롬프트:**

```
@public-dataset/business-docs/references/지난제안서.md 의 내용으로 발표 덱을 만들어줘.
디자인은 @public-dataset/ppt/ictk_deck_template.pptx 를 그대로 따르고,
스펙은 @public-dataset/ppt/ictk_deck_template.DESIGN.md 에 정리돼 있어.

- 캔버스 20 x 11.25 inch (1920x1080 px 설계, px x 0.75 = pt)
- 본문 슬라이드 공통 골격을 지킬 것: 제목 y=0.83 / 킥커 y=1.62 / 구분선 y=2.35 /
  푸터 y=10.22, 좌우 여백 1.15
- 제안서의 절마다 성격에 맞는 레이아웃(A~J)을 고르고, 왜 그 레이아웃인지 한 줄로 적어줘
- 슬라이드마다 "한 줄 요약(킥커)"을 반드시 채울 것. 원문에 없으면 그 절을 읽고 새로 쓸 것
- 우측 네이비 패널에는 그 슬라이드의 결론 한 문장만
- 표지의 사명·클로징 연락처는 제안사(주식회사 세이프칩) 기준으로 교체
- Style Guide 슬라이드(1번)는 결과물에서 제외
- PptxGenJS 스크립트로 만들고, 공통 골격은 함수로 빼줘
```

**확인 지점.** 결과물이 이 넷을 통과하면 잘 나온 것이다.

1. 슬라이드마다 킥커(한 줄 요약)가 채워져 있는가 — 원문에 없는 문장을 만들어야 하므로 여기서 제일 많이 빈다
2. 우측 패널에 결론이 한 문장으로 들어갔는가, 아니면 본문이 그대로 복사됐는가
3. 여백 1.15와 푸터 y=10.22가 전 슬라이드에서 같은가
4. 표(2절·6절)가 이미지가 아니라 도형·텍스트로 만들어졌는가

## 걸려 넘어지는 지점

실습의 알맹이는 여기다. 그냥 "분석해줘"로는 안 나오고, 틀린 채로 그럴듯한 결과가 나온다.

### 두 덱 공통

- **`theme1.xml`을 믿으면 틀린다.** 두 덱 모두 테마가 Office 기본값(Calibri + 파랑 `4F81BD`)으로 남아 있고 실제 디자인과 무관하다. 진짜 색은 `ppt/slides/slideN.xml`의 `srgbClr val=`에 있다.
- **캔버스가 표준 크기가 아니다.** PowerPoint 기본 와이드는 13.333 × 7.5 inch인데 두 덱 다 20 × 11.25 inch다. 비율은 같지만 좌표계가 1.5배라, 기본 크기로 만들고 원본 좌표를 쓰면 요소가 화면 밖으로 나간다.

### `ictk_deck_template` 쪽

- **선언과 실제가 다르다.** Style Guide 슬라이드는 Pretendard라고 적어 놨는데 XML에는 Noto Sans KR이 박혀 있다. 문서는 의도, XML은 사실이다.
- **pt가 px 설계의 0.75배다.** 39pt를 40pt로 반올림하면 좌표 계산이 계속 어긋난다. 52px 기준으로 잡고 마지막에 ×0.75 한다.
- **공통 골격을 슬라이드마다 다시 그리면 어긋난다.** 제목·킥커·구분선·푸터 y좌표는 고정이므로 함수로 뺀다.

### `creative_brief_deck` 쪽

- **폰트가 상용이고 파일에 임베드돼 있다.** `ppt/fonts/font16~19.fntdata`에 들어 있어 원본은 정상으로 보이지만, 새 덱에서 같은 폰트명을 쓰면 로컬에 없어 대체 폰트로 렌더된다. 한글 덱이면 Pretendard 계열로 치환한다.
- **사진 16장이 디자인의 절반인데 `<p:pic>`으로는 안 잡힌다.** Canva는 사진을 그룹 안 도형의 `blipFill`로 넣기 때문에 python-pptx에서 `shape.shape_type == PICTURE`로 훑으면 **0개가 나온다.** 그룹을 재귀로 들어가야 하고 좌표도 그룹 좌표계를 거쳐야 한다.

## 그 외 연습 예시

- 슬라이드별 텍스트 추출 → 목차/구조 문서 만들기
- 발표자 노트만 뽑아 진행 대본 만들기 (`ictk_deck_template`에 15개 있음)
- pptx → 마크다운/PDF 변환
- `ppt/media/`에서 이미지만 일괄 추출
- 용량 큰 덱의 내장 이미지 재압축해 파일 줄이기 (`creative_brief_deck`이 그 결과물이다)

## 주의

- `ictk_deck_template.pptx`에는 **ICTK 브랜딩**(사명·주소·전화·`ictk.com`·`Safe with us`·색 팔레트)이 남아 있다. 레이아웃 실습용으로만 쓰고, 다른 목적으로 배포할 자료를 만들 때는 브랜딩부터 교체한다. 실제 IR 수치·기술 내용은 들어 있지 않다(전부 플레이스홀더).
- `creative_brief_deck.pptx`의 **원본은 Canva 무료 템플릿**이다. 실습·학습 용도로만 쓰고, 상용 배포물이나 판매 콘텐츠에 그대로 넣지 말 것. Canva 콘텐츠 라이선스는 템플릿 파일 자체의 재배포를 제한한다. 재현해서 만든 결과물은 내용·이미지가 우리 것이면 문제없다.
- `creative_brief_deck.pptx`는 저장소에 넣기 전 내장 JPEG을 **장변 1920px·품질 80**으로 재인코딩했다(39.4MB → 5.3MB). 레이아웃·텍스트·구성은 원본 그대로이고 파트 개수도 동일(75개)다.
- 두 덱 다 본문이 플레이스홀더다. **디자인 재현용 입력**이지 독해용이 아니다. 한국어 본문이 필요하면 `business-docs/`를 함께 쓴다(위 대표 실습이 그 조합이다).
